🔑 PGP-Verschlüsselung einfach erklärt

Was ist PGP?

PGP (Pretty Good Privacy) ist wie ein digitales Schloss mit zwei Schlüsseln:

🔓

Public Key (Öffentlich)

Zum Verschlüsseln

✅ Wird im System gespeichert

✅ Jeder kann ihn sehen

✅ Kann nur verschlüsseln (nicht entschlüsseln)

Wie ein Briefkasten: Jeder kann Briefe einwerfen

🔐

Private Key (Geheim)

Zum Entschlüsseln

❌ NIEMALS im System gespeichert

❌ Nur der Besitzer kennt ihn

❌ Kann nur entschlüsseln (nicht verschlüsseln)

Wie ein Briefkastenschlüssel: Nur der Besitzer kann öffnen

⚠️ Wichtig: Der Private Key bleibt IMMER beim Nutzer (auf USB-Stick, Hardware-Key, verschlüsseltem Speicher). Das System kennt ihn nie!

✉️ Zwei Wege zum Verschlüsseln

🔐

Auto-Encrypt Modus

Das System verschlüsselt automatisch

✅ Einfach zu benutzen

✅ Keine externe Software nötig

✅ Klartext eingeben → System verschlüsselt

⚠️ Empfänger muss Public Key hinterlegt haben

📝

Manual Modus

Bereits verschlüsselte Nachricht einfügen

✅ Maximale Kontrolle

✅ Verschlüsselung auf eigenem Gerät

✅ Funktioniert auch ohne Public Key im System

⚠️ Externe PGP-Software erforderlich

📤 Nachricht verschicken (Encryption Flow)

Modus 1: Auto-Encrypt (Automatisch)

Schritt 1: Klartext eingeben Du schreibst: "Ihre Bestellung wurde versandt"
⬇️
Schritt 2: System holt Public Key des Empfängers System lädt Public Key von Alice aus der Datenbank
⬇️
Schritt 3: Verschlüsselung System verschlüsselt mit Public Key → -----BEGIN PGP MESSAGE-----...
⬇️
Schritt 4: Verschlüsselte Nachricht speichern Nur die verschlüsselte Version wird in der Datenbank gespeichert ✅

Modus 2: Manual (Manuell verschlüsselt)

Schritt 1: Nachricht extern verschlüsseln Du verwendest deine eigene PGP-Software (z.B. GPG, Kleopatra)
⬇️
Schritt 2: Verschlüsselten Text einfügen Du fügst ein: -----BEGIN PGP MESSAGE----- hQEMA... -----END PGP MESSAGE-----
⬇️
Schritt 3: System validiert Format System prüft: Beginnt mit -----BEGIN PGP MESSAGE-----? ✅
⬇️
Schritt 4: Speichern Verschlüsselte Nachricht wird gespeichert ✅
✅ Sicherheits-Check: Das System akzeptiert KEINE Klartextnachrichten. Jede Nachricht wird vor dem Speichern geprüft. Ist sie nicht verschlüsselt, wird sie abgelehnt!

📥 Nachricht lesen (Decryption Flow)

Schritt 1: Thread öffnen Du siehst: -----BEGIN PGP MESSAGE----- hQEMA... -----END PGP MESSAGE-----
⬇️
Schritt 2: "🔓 Decrypt Message" klicken Ein Modal-Fenster öffnet sich
⬇️
Schritt 3: Private Key + Passphrase eingeben Du fügst deinen Private Key ein (z.B. von USB-Stick kopiert)
Optional: Passphrase falls dein Key verschlüsselt ist
⬇️
Schritt 4: AJAX Request an Server Browser sendet: Private Key + Passphrase + Message ID an Server
⬇️
Schritt 5: Server entschlüsselt (temporär) Server erstellt temporäres GPG-Verzeichnis (~100ms)
Importiert Private Key → Entschlüsselt → Gibt Klartext zurück
⬇️
Schritt 6: Klartext anzeigen Browser zeigt: "Ihre Bestellung wurde versandt" ✅
⬇️
Schritt 7: Cleanup (Aufräumen) Server: Temporäres GPG-Verzeichnis gelöscht ✅
Browser: Private Key Input-Feld geleert ✅
⚠️ Zero-Knowledge Prinzip: Der Private Key existiert nur für ~100 Millisekunden auf dem Server und wird NIEMALS gespeichert. Danach ist er komplett gelöscht!

🛡️ Warum Private Keys NIEMALS gespeichert werden

❌ Wenn Private Keys AUF Server (UNSICHER)

Angriffs-Szenario: Datenbank-Hack

1️⃣ Angreifer erhält DB-Zugriff

⬇️

2️⃣ Bekommt ALLE Private Keys

⬇️

3️⃣ Bekommt ALLE verschlüsselten Nachrichten

⬇️

4️⃣ Kann ALLES entschlüsseln

⬇️

💥 TOTALE KOMPROMITTIERUNG

Single Point of Failure: SERVER

Wenn Server kompromittiert = ALLE Nachrichten lesbar

✅ Private Keys OFF Server (SICHER - Aktuelles System)

Angriffs-Szenario: Datenbank-Hack

1️⃣ Angreifer erhält DB-Zugriff

⬇️

2️⃣ Bekommt Public Keys (nutzlos allein)

⬇️

3️⃣ Bekommt verschlüsselte Nachrichten

⬇️

4️⃣ KANN NICHT entschlüsseln (keine Private Keys)

⬇️

✅ Nachrichten bleiben SICHER

Zero-Knowledge: ✅

Server kann Nachrichten nicht lesen

Selbst mit vollem DB-Zugriff bleiben Nachrichten unleserlich

📊 Was der Server weiß vs. nicht weiß:

✅ Server WEISS:

  • Wer mit wem kommuniziert (Metadaten)
  • Wann Nachrichten gesendet wurden
  • Public Keys aller Nutzer
  • Länge der verschlüsselten Nachrichten

❌ Server WEISS NICHT:

  • Inhalt der Nachrichten
  • Private Keys der Nutzer
  • Passphrasen

🏰 Defense in Depth - Mehrschichtige Sicherheit

Das System verwendet mehrere Sicherheitsebenen (wie Zwiebelschalen):

1
Eingabe-Validierung

Nur gültige PGP-Nachrichten werden akzeptiert

2
Code-Level Checks

Vor dem Speichern: if not message.is_encrypted: raise ValueError

3
Datenbank-Verschlüsselung

Nachrichten als BYTEA (verschlüsselt) gespeichert, nicht als TEXT

4
Zero-Knowledge Decryption

Private Key nur temporär (~100ms), dann gelöscht

5
Access Control

Nur Empfänger kann entschlüsseln (recipient_id Check)

6
Rate Limiting

10 neue Threads/Stunde, 20 Antworten/Stunde (verhindert Spam)

7
Auto-Deletion

Nachrichten werden nach 30 Tagen automatisch gelöscht (OPSEC)

💡 Best Practices für Nutzer

✅ EMPFOHLEN:

  • Hardware Security Key - YubiKey, Nitrokey
  • Verschlüsselter USB-Stick - VeraCrypt Container
  • Password Manager - 1Password, Bitwarden (verschlüsselt)
  • Offline Computer - Air-Gapped System für Schlüsselverwaltung
  • Starke Passphrase - Mindestens 20 Zeichen für Private Key
  • Backup - Verschlüsselte Kopien an mehreren sicheren Orten

❌ NIEMALS:

  • ❌ Private Key in Cloud-Speicher (Google Drive, Dropbox, etc.)
  • ❌ Private Key per E-Mail versenden
  • ❌ Private Key unverschlüsselt auf Festplatte speichern
  • ❌ Private Key in Screenshots
  • ❌ Private Key auf öffentlichen Computern eingeben
  • ❌ Private Key mit anderen Personen teilen
